# TravelPlan + Supabase

## Что уже подключено

В проект добавлены:

- `js/supabaseClient.js` - ключи и клиент Supabase.
- `js/db.js` - функции для отзывов, бронирований, статистики и мест.
- `supabase_setup.sql` - SQL-команды для создания таблиц и политик.
- `index.html` - подключён Supabase CDN и новые JS-файлы.

## Что сделать в Supabase

1. Открой Supabase Dashboard.
2. Открой свой проект.
3. Перейди в `SQL Editor`.
4. Создай новый query.
5. Вставь весь файл `supabase_setup.sql`.
6. Нажми `Run`.

## Как проверить

Открой сайт в браузере и зайди в DevTools -> Console.

Если всё нормально, будет сообщение:

```text
Supabase подключён: []
```

Если таблицы ещё не созданы, будет предупреждение. Это нормально: сначала выполни SQL.

## Важно

В файл вставлен publishable key. Это публичный ключ, его можно использовать на фронтенде.
Нельзя вставлять в сайт service_role / secret key.

## Новое в этой версии

### Аккаунты
В Supabase включи:

1. Authentication → Providers → Email → Enable
2. Для дипломного демо можно выключить `Confirm email`, чтобы регистрация сразу входила в аккаунт.
3. Authentication → Providers → Google → Enable, если нужен Google-вход.
4. Для Google добавь redirect URL своего сайта, если публикуешь на GitHub Pages.

### Профили
Выполни `supabase_setup.sql` заново. Он создаёт таблицу `profiles` и добавляет к `bookings` поля:

- `user_id`
- `user_email`

Профиль хранит:

- имя;
- ник;
- аватарку;
- город;
- стиль путешествий;
- бюджет.

### Бронирования
Новые брони создаются только после входа в аккаунт и сохраняются в Supabase. На странице «Мои бронирования» пользователь видит свои брони через RLS.

### Отзывы
Имя больше не вводится руками. Отзывы публикуются от имени профиля, а если пользователь не вошёл, используется «Гость».

### Отзывы мест
В модалках интересных мест появились отзывы с оценкой и комментарием.

## Update: картинки в отзывах и seed интересных мест

1. Открой `supabase_setup.sql` и выполни его в Supabase SQL Editor. Он добавит:
   - `reviews.user_id`
   - `reviews.image_url`
   - новые policies для отзывов.

2. Потом открой `supabase_seed_places.sql` и выполни его отдельно. Он заполнит таблицу `places` всеми интересными местами из сайта.

Важно: `supabase_seed_places.sql` сначала очищает `public.places`, а потом вставляет полный список заново. Это сделано специально, чтобы не плодить дубликаты при повторном запуске.

3. В отзывах теперь можно прикрепить картинку файлом или вставить ссылку на фото. Для демо файл сохраняется как data URL прямо в поле `image_url`. Для настоящего продакшена лучше потом подключить Supabase Storage, потому что база данных не должна жить как фотоальбом бабушкиного телефона.

## Картинки на сайте

В этой версии сайт сначала ищет локальные картинки в папке `assets/images`.

### Города
Путь:

```text
assets/images/cities/<slug>.jpg
```

Примеры:

```text
assets/images/cities/almaty.jpg
assets/images/cities/astana.jpg
assets/images/cities/bangkok.jpg
```

### Отели
Путь:

```text
assets/images/hotels/<slug-названия-отеля>.jpg
```

Пример:

```text
assets/images/hotels/kazakhstan-hotel.jpg
```

### Интересные места
Путь:

```text
assets/images/places/<slug-города>-<slug-места>.jpg
```

Пример:

```text
assets/images/places/almaty-kok-tobe.jpg
```

Если локальной картинки нет, сайт покажет внешнюю запасную фотографию, чтобы карточка не была пустой.
